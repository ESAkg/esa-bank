# ESA Bank — онлайн-банкинг (демо-проект)

Полноценное веб-приложение интернет-банка: регистрация, вход, восстановление
пароля, переводы между клиентами по номеру телефона и по QR-коду, история
операций. У каждого клиента свой уникальный ID и счёт.

## Что нового в этой версии

- **`index.html` теперь лежит прямо в корне проекта** — открыв папку, вы
  сразу видите сайт, а не ищете его внутри `public/`. Весь серверный код и
  файл базы данных переехали в подпапку `server/` и физически не могут
  быть отданы браузеру напрямую (сервер явно это блокирует — проверено).
- **Добавлен аккаунт владельца банка** с безлимитным балансом (подробности
  ниже).
- **База данных теперь может быть онлайн.** Если вы развернёте приложение
  на бесплатном хостинге (Render, Railway и т.п.), диск там обычно не
  постоянный — при каждом новом деплое файл данных обнулялся бы. Теперь
  можно подключить бесплатную облачную базу Supabase, и все данные будут
  жить в интернете, а не на конкретном сервере.
- **Запускать `node server.js` руками больше не обязательно.** Когда
  приложение развёрнуто на хостинге, он сам выполняет команду запуска —
  вы просто открываете ссылку в браузере. Команда нужна только если вы
  тестируете проект у себя на компьютере.

| Телефон | +996 995 223 667 |
| Пароль | 001esakg |
| Баланс | Безлимитный — на главном экране и в профиле вместо числа показывается надпись «Безлимиттүү» |

Как это работает технически: при переводе с этого счёта сумма у
получателя увеличивается как обычно, а баланс владельца не уменьшается
(это счёт-эмитент, как касса банка). Если перевод отправить **на** этот
счёт, баланс владельца тоже не растёт до абсурдных цифр — остаётся
безлимитным.

**Важно по безопасности:** этот пароль и телефон сейчас видны прямо в
исходном коде (в файле `server/server.js`, в функции создания начальных
аккаунтов) — это нужно, чтобы аккаунт создался автоматически при первом
запуске. Если вы выложите репозиторий в **публичный** доступ на GitHub,
эти данные увидит любой. Рекомендации:
1. Либо держите репозиторий приватным (на GitHub это бесплатно).
2. Либо после первого запуска смените пароль владельца (функции смены
   пароля из профиля пока нет в интерфейсе — могу добавить по запросу) и

## Запуск локально (для разработки и тестов у себя на компьютере)

Нужен Node.js версии 18 или новее.

```bash
node server/server.js
```

Откройте **http://localhost:3000** — это всё, зависимостей для установки
нет (`npm install` ничего не скачивает).

## Онлайн-база данных (Supabase) — уже готова

Проект Supabase для ESA Bank уже создан (`ESA bank`, Stockholm/eu-north-1),
таблица `kv_store` в нём тоже уже создана через SQL Editor:

```sql
create table if not exists kv_store (
  key text primary key,
  value jsonb not null,
  updated_at timestamptz default now()
);
alter table kv_store enable row level security;
create policy "esa bank backend" on kv_store for all using (true) with check (true);
```

Приложению для перехода в онлайн-режим нужны две переменные окружения:

- `SUPABASE_URL` = `https://iuxnvtjvcqgyufzgjwnj.supabase.co`
- `SUPABASE_KEY` = ваш **secret key** (новый формат, начинается на
  `sb_secret_...`, из **Project Settings → API Keys → Secret keys**)

**Куда их вставлять:** только в переменные окружения хостинга (Render,
Railway и т.п. — см. раздел ниже) или в локальный файл `.env` у себя на
компьютере (он уже в `.gitignore`, в репозиторий не попадёт). **Никогда
не вставляйте secret key в файлы, которые загружаете на GitHub** — это
ключ с правами администратора базы, он должен оставаться только на
сервере.

Используется именно **secret key**, а не publishable key — потому что
обращения к Supabase идут из серверного кода (`server/db/store.js`), а
не из браузера, поэтому ограниченный publishable-ключ тут не подходит:
он не проходит на корневой `/rest/v1/` эндпоинт с правами на запись.

Без этих переменных приложение продолжает работать на локальном файле —
ничего не сломается, если вы решите пока не подключать онлайн-базу.

**Как проверить, что онлайн-база реально работает:** запустите
приложение (локально с `.env`, либо уже задеплоенное на хостинге),
зарегистрируйте тестового пользователя или сделайте перевод, затем
откройте в Supabase **Table Editor → kv_store** — там должна появиться
одна строка с ключом `esa_bank_main`, в которой лежат все данные банка.
Если строка появилась и обновляется после ваших действий в приложении —
онлайн-база подключена верно. Напрямую протестировать это соединение из
данной рабочей сессии я не могу (здесь нет доступа к произвольным
внешним сайтам, только к менеджерам пакетов), поэтому первую проверку
нужно сделать на реальном запуске — локально у себя или уже на хостинге.

## Публикация в интернете, чтобы получить ссылку

**Render.com** (бесплатно, без карты):

1. Зарегистрируйтесь на [render.com](https://render.com) через GitHub.
2. Сначала выложите этот проект в свой репозиторий на GitHub (см. раздел
   ниже).
3. На Render: **New → Web Service** → выберите ваш репозиторий `esa-bank`.
4. Настройки:
   - **Build Command:** `npm install`
   - **Start Command:** `npm start` (это выполнит `node server/server.js`)
   - **Instance Type:** Free
5. Если настроили Supabase — на вкладке **Environment** добавьте
   `SUPABASE_URL` и `SUPABASE_KEY` со значениями из шага выше.
6. Нажмите **Create Web Service**. Через 1–2 минуты Render выдаст ссылку
   вида `https://esa-bank.onrender.com` — с этого момента вы (и любой, у
   кого есть ссылка) просто открываете её в браузере. Команду `node
   server.js` вводить никогда не нужно — хостинг делает это сам при
   каждом старте.

Альтернативы: **Railway.app**, **Cyclic.sh** — процесс похожий (указать
GitHub-репозиторий, Start Command `npm start`, при необходимости те же
переменные окружения).

Затем на [github.com](https://github.com) создайте пустой репозиторий (без
README/лицензии) и выполните команды, которые GitHub покажет на странице
нового репозитория:

```bash
git branch -M main
git push -u origin main
```

Если репозиторий уже существует и вы хотите, чтобы я запушил изменения
напрямую — назовите мне `владелец/название` репозитория, и я это сделаю.

## Возможности

- Регистрация, вход, восстановление пароля по коду (SMS-шлюз пока не
  подключён — это платная услуга с отдельным провайдером; до его
  подключения код восстановления показывается прямо на экране, чтобы
  функция оставалась рабочей)
- Личный счёт с уникальным номером и ID клиента
- Аккаунт владельца банка с безлимитным балансом
- Перевод по номеру телефона и по QR-коду между клиентами
- История операций (входящие и исходящие)
- Экран «Перевод в обработке» → «Успешно» с чеком
- Онлайн-база данных (опционально) или локальный файл — данные не
  теряются ни при перезапуске, ни при передеплое (если подключён Supabase)

## Что можно улучшить дальше

- Смена пароля из профиля (сейчас только через «Забыли пароль»)
- Подключить настоящий SMS-шлюз для кодов восстановления
- Лимиты на количество попыток входа (защита от перебора пароля)
- Карты, депозиты, кредиты — как на референс-макетах — следующим этапом
